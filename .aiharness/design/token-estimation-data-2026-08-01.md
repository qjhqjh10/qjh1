# ④ token 估算精度优化 — 实测数据与实施记录（2026-08-01）

> 遗留决策 4 已完成。系数：**CJK 1.2 字符/token、Latin 4.5 字符/token**（原 1.8/4）。

## 一、权威测量（直接请求 usage 反推，无缓存干扰）

用 `scripts/measure-token-density.mjs` 构造已知字符数文本 → `chat.completions` 返回 `usage.prompt_tokens`（每次全新请求，无缓存命中）：

| 样本 | 字符数 | tokens | 字符/token |
|---|---|---|---|
| 空消息（固定开销） | 0 | 83 | — |
| 纯中文（无标点） | 1000 | 583 | 1.72 |
| **中文小说段落（真实文本）** | 544 | 459 | **1.19** |
| 中文+全角标点 | 1260 | 1163 | 1.08 |
| 纯英文 | 2670 | 594 | 4.49 |
| 中英混合 | 2680 | 1084 | 2.47 |
| JSON | 451 | 338 | 1.33 |
| Markdown 章节 | 1090 | 783 | 1.39 |

**结论**：真实中文写作场景 ≈1.2 字符/token（原 1.8 低估 1.5 倍，与文档假设一致）。取 **1.2**（真实小说 1.19 贴切；纯汉字场景高估 43% 属安全方向，标点密集场景低估 10% 可接受）。英文实测 4.49 → **4.5**。

## 二、实施

- `src/agent/utils/tokenEstimation.ts`：`cjk / 1.8 → 1.2`、`latin / 4 → 4.5`（注释含实测依据）
- 全量回归：tsc + 558 passed + 15 skipped（零破坏——ContextCompressor 的 getStage 测试直接传 usedTokens 不依赖估算；estimateTokens 断言区间兼容）
- 对话场景 S1/S2/S8 通过（压缩/上下文机制无回归）

## 三、已知局限（后续可选优化）

1. **场景级估/真对比口径不可比**：DeepSeek Anthropic 兼容接口的 `input_tokens` 疑似只统计**缓存未命中**部分（S1 场景大量缓存命中 → 真实仅 1212 tokens，估算全量 5689）——估/真比值在缓存场景下无统计意义。系数决策以直接测量为准。
2. **固定开销**：单条空消息请求 = 83 tokens（DeepSeek 系统级开销）。`estimateMessages` 的 +4/条 与 83 的差距在短消息场景下显著；影响范围：进度条精度。后续可考虑按实际格式开销校准。
3. **标点密度差异**：全角标点（1.08）比汉字（1.72）密——若追求极致精度可按字符类别分档（当前统一 1.2 已足够贴近真实混合文本）。
