- **主/子 agent 分工强化（对齐 orchestrator-worker 最佳实践，用户决策）**: V4SystemPrompt 新增「重任务优先委托」原则——大文件读取/分析（>2万字符）、长文件精确修改、知识库深度分析、多文件综合总结 → 优先委托子代理（analyze_file/edit_file_task/kb_analyze，独立上下文只回传摘要，主 agent 上下文保持轻量；简单任务直接用工具不委托）；read_file 超 50 万字符（MAX_READ_CHARS）截断提示追加委托引导（建议 analyze_file 或 offset/limit 分段读）——主 agent 硬扛超大文件的最后闸门。委托机制真相（用户询问）：子代理工具集受限（角色限定 ≤7 只读工具、内部无委托工具不能二次委托）；主 agent 后续 15 核心常驻含 5 个委托工具；委托决策 = 工具描述阈值（2 万字符）+ 提示词原则（软约束）+ 截断反馈自愈；read_file 结果保留 5 工具轮（PRESERVE_TOOL_TURNS=5）后折叠为摘要需重读——大文件优先 kb_analyze 正因此
- **主/子 agent 人设隔离确认 + 角色角度传递（用户提醒）**: 子代理上下文 = ROLE_PROMPTS 独立提示词 + 任务消息（SubagentService.setContextAssembler——无对话历史/无角色模板注入/无 KB 预注入），主 agent 角色扮演人设不会污染子代理（子代理不知道主 agent 在扮演谁）✓；唯一缺口已补——角色设定文件提示词引导主 agent 委托 kb_analyze 时在 query/focus 传**角色扮演分析角度**（角色性格/关系/说话风格/世界观约束/行为准则与禁忌，而非泛泛资料摘要——子代理看不到扮演设定，角度须由主 agent 传入；kb_analyze 总结经 [子代理快照] 跨轮复用，角度决定扮演一致性）
