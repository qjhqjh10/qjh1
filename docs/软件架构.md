## v14.1.1 架构变化（子 agent 上下文隔离）

- **子 agent 委托**: `analyze_file`（只读子代理）/ `edit_file_task`（读写子代理）→ SubagentService 组装独立 V4UnifiedRuntime（isolatedStore + 64K 窗口 + 独立审计 + 双协议 adapter），主 agent 只接收结构化 detail——大文件读写不再撑爆主上下文
- **isolatedStore**: V4AgentConfig 新增，子 agent run 完全隔离共享 AgentStore（UI 状态与熔断器不受污染）；SERIAL_TOOLS 串行执行防双子代理并发；per-tool 超时查表（子代理 300s / analyze_text_style 180s）
- **tokens 主/子分开**: V4AgentRunResult.subAgentUsage 贯穿 ToolExecutor→Runtime→Bridge→UI 消息页脚（紫色"子代理 入/出/合计"）；billedTokens 主口径不变；全局 usage.jsonl 自动覆盖子代理调用
- **子代理提示词内置青剑工具约定**: batch_replace 全局替换 / __FULL_REPLACE__ / old_string 匹配不唯一处理（实测 150 处替换成功）
- **测试**: SubagentService 5 + subagentTools 7 + V4RuntimeSubagent 4；对话场景 S_SUB1（大文件分析）/ S_SUB2（长文件修改）
- **工具 27→29**；渐进披露 SUBSEQUENT_TOOL_NAMES +2；对话场景 22→25


## v14.2.0 架构变化（跨 run 续跑 + 批量并行 + 验收子代理）

- **跨 run 续跑**: `V4AgentRunResult.taskProgress`（{tasks:[{id,desc,done}], allDone, interrupted}）——interrupted 仅在 4 种中断标记（用户中止/超时/API失败/迭代耗尽；正常完成与提问不标记）；BridgeSendResult 透传 → AIChatWindow 存 assistant 消息字段（IndexedDB 自动持久化）→ `maybeInjectResume`（utils.ts 纯函数，单测 7 用例）在 handleSend 时检测上一条消息未完成 → 注入 `[续跑] 上次中断于 X/Y` system 提示。对话场景 S_RESUME
- **批量并行分析**: ToolExecutor `SERIAL_TOOLS` 拆分为 `PARALLEL_READ_TOOLS`（analyze_file，分片 ≤3 并发）/ `SERIAL_WRITE_TOOLS`（edit_file_task 串行）；V4UnifiedRuntime 普通只读全量并行 + 子代理只读分片并行。对话场景 S_PAR
- **验收子代理**: 第 3 角色 `verify`（复用只读工具集）+ `verify_task` 工具（第 30 工具；JSON 报告 {passed, items} 解析为结构化 detail）；V4UnifiedRuntime 清单完成且写过文件时注入一次 `[验收提示]`（不强制，_verifyHintInjected 防重复）。对话场景 S_VERIFY
- **子代理窗口跟随配置**: runSubagent contextWindow 默认从硬编码 64K 改为 modelConfig.contextWindow ?? 128K（与主 agent 一致，可达 1M）
- **tokens 按来源统计**: logTokenUsage entry 加 `source`（main/subagent/pipeline/image）；ai:chat/chat-stream 标 pipeline、子代理 adapter 标 subagent；TokenStatsTab 来源筛选 + bySource 分布
- **并行委托竞态修复**: subagentTools getSettingsStore / createSubagentAdapter 用 promise 缓存共享模块引用（vitest 并发动态 import 竞态 + 生产减少重复解析）
- **Anthropic 统计口径修复**: cacheHitTotal 只含 cache_read（cache_creation 按输入价计费）
- **UI 情色→涩涩**: 20 文件显示层替换（数据 value/提示词/softwareGuide 不动）
- **测试**: 498→520；对话场景 25→28

## 上下文注入架构 (v13.2.0)

```
每轮注入:
  system[0]: 核心规则 (~3,600 tokens, System Prompt 瘦身后)
  system[1]: 角色模板 (可选，固定前缀)
  tools:     首轮 27 个，后续 12 核心 + tool_search 动态发现

System Prompt 从 ~5,800 tokens 瘦身到 ~3,600 tokens (写作规范手册 12 节→7 个外部模板文件)。
Prompt 缓存 (DeepSeek 前缀缓存 + Anthropic cache_control) 减免固定开销费用 90%+。

BridgeContextBuilder 负责：
  - 核心规则 (始终全量)
  - 角色模板注入
  - KB 搜索 + Web 搜索 (动态)
  - 项目信息注入
  - Token 估算

ContextCompressor: 3 阶段渐进压缩 (70%/80%/90%)
cleanOldReadResults: 超过 5 轮 read_file 结果压缩
ContractExecutor: 写工具去 detail

上下文进度条: 使用 estimatedContextTokens (基于 messagesForApi 真实大小)
```

## 核心功能

- **小说创作**: 大纲(10Tab) → 细纲 → 章节写作(编辑器+AI生成+风格/场景模板注入)
- **小说仿写**: 导入TXT → 13种类型 → 逐章提取 → 聚合 → 风格分析 → 大纲/细纲模仿
- **小说续写**: 导入TXT → 13维度逐章分析 → 原作理解 → 续写章节 (7步)
- **章节生成**: 四层提示词(风格→剧情→场景→参考) + 流式输出 + 温度调节
- **风格/场景工坊**: 模板创建和管理
- **故事脉络**: 多维度分析 + 冲突检测
- **知识库**: PDF/DOCX/TXT → 语义搜索
- **导出**: EPUB 3.0
- **设置**: 多模型管理 + Token统计 + 双协议切换 + 角色模板
- **对话测试**: 28 场景 (25 原有 + S_RESUME 跨run续跑 + S_PAR 批量并行 + S_VERIFY 验收)
