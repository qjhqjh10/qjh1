## 〇、设计原则

```
用户不会说"调用create_file创建角色"。
用户说:"我想加个反派，亦正亦邪那种，和主角有点恩怨纠葛，你帮我设计一下。"

一个真实输入 = 多个隐含意图 + 情绪 + 模糊表达 + 背景信息
AI的真正能力 = 理解 → 拆解 → 排序(按依赖) → 执行 → 纠错 → 汇报
```

**三版演进**：

| | v1 单意图基准 | v2 多意图理解 | v3 全功能深度融合 |
|---|---|---|---|
| 覆盖 | 技能触发 | 意图拆解 | 全功能+全协议+全场景 |
| 用户语言 | 指令式 | 自然对话 | 完全真实(含口误/修改/情绪) |
| Anthropic | L2补充 | 未专门设计 | **核心测试层** |

## 二、★ L2 — Anthropic 协议全栈测试

> 这是V4架构的核心路径：`DeepSeek /anthropic 端点 → SSE流式 → content_block解析 → 工具调用 → 多轮循环 → 上下文压缩`

### 2.1 流式解析 (Stream Parsing)

| ID | 场景 | 输入模拟 | 预期 |
|----|------|---------|------|
| A-STR-01 | 纯文本流 | 单content_block(text_delta×N) | 正确拼接, 无多余空白 |
| A-STR-02 | 流中断 | 文本流中突然断开 | 返回已收集文本, 状态标记为partial |
| A-STR-03 | 空流 | 服务端返回空body | 返回空文本, 不崩溃, msg="[空响应]" |
| A-STR-04 | 中文流 | 大段中文逐字到达(含标点/换行) | 正确拼接, 无乱码, 换行保留 |
| A-STR-05 | 流中混杂 | text_delta和input_json_delta交替 | 各自正确累积, 不互相污染 |
| A-STR-06 | 延迟首token | 2秒后才开始stream | timeout机制不误触发, 正常接收 |
| A-STR-07 | 极长流 | 连续100+ text_delta | 内存不泄漏, 拼接正确 |
| A-STR-08 | 多content_block | 1个text+2个tool_use交织 | text归text, tool归tool |

### 2.2 工具调用 (Tool Calling)

| ID | 场景 | 操作 | 验证点 |
|----|------|------|--------|
| A-TC-01 | 单工具 | AI调用read_file | tool_use解析正确, 参数完整, 执行成功 |
| A-TC-02 | 多工具并行 | 同时调用read_file+list_directory | 并行执行, 都返回结果, 结果不互相覆盖 |
| A-TC-03 | 读写分离 | read×2 + create×1 同时 | 读工具并行执行, 写工具串行(在读之后) |
| A-TC-04 | 工具参数JSON | 复杂嵌套参数 | input_json_delta正确累积为完整JSON |
| A-TC-05 | 工具参数未完成 | input_json在最后一个delta不完整 | Runtime能检测并标记为error |
| A-TC-06 | 未知工具 | AI调用不存在的工具名 | 返回error, 不崩溃, AI收到error后换策略 |
| A-TC-07 | 参数缺失 | AI少传了required参数 | 工具正确返回error, AI重试时补全 |
| A-TC-08 | 工具超时 | 工具执行超过60秒 | Promise.race触发超时, 返回error |
| A-TC-09 | 工具失败→重试 | 第一次edit_file失败(old_string不匹配) | AI读取error→分析原因→重试→成功 |
| A-TC-10 | 批量工具 | 一轮中8+个工具调用 | 全部执行, 不遗漏, 结果按顺序注入上下文 |
| A-TC-11 | 嵌套工具依赖 | 第一个工具的结果需要传给第二个 | AI读取结果后正确调整下一轮工具参数 |
| A-TC-12 | 工具+文本混合 | AI同时返回text和tool_use | text先注入, tool结果紧跟, 顺序正确 |

| ID | 场景 | 模拟过程 | 验证点 |
|----|------|---------|--------|
| A-MT-01 | 2轮对话 | 用户说A→AI回复→用户说B(引用A的结果) | 上下文保留, AI知道"那个角色"指谁 |
| A-MT-02 | 5轮连续工具 | 每轮都调工具, 最终回复 | 不超过maxIterations, 结果递增正确 |

### 2.5 异常处理 (Error Handling)

| ID | 场景 | 触发方式 | 验证点 |
|----|------|---------|--------|
| A-ERR-01 | API 401 | 无效API Key | 返回明确错误信息, 不无限重试 |
| A-ERR-02 | API 429 | 速率限制 | 等待后重试1次, 仍失败则告知用户 |
| A-ERR-03 | API 500 | 服务端错误 | 重试1次, 仍失败则告知用户+记录日志 |
| A-ERR-04 | API 超时 | 90秒无响应 | 超时错误信息清晰, 不hang住 |
| A-ERR-05 | 网络断开 | fetch抛出ECONNREFUSED | 识别为瞬态错误, 重试, 最终反馈 |
| A-ERR-06 | SSE格式错误 | 返回非标准SSE数据 | parseSSE不崩溃, 跳过异常chunk继续 |
| A-ERR-07 | JSON解析失败 | input_json_delta包含非法JSON | 标记该工具调用为error, 不崩溃 |
| A-ERR-08 | 首轮API就失败 | 第一条消息就出错 | 不进入循环, 直接返回错误 |
| A-ERR-09 | 第3轮失败 | 前2轮正常, 第3轮API 503 | 保留前2轮结果, 报第3轮的错 |
| A-ERR-10 | 连续3次失败 | 触发circuit breaker | 熔断生效, cooldown后尝试恢复 |

## 三、★ L3 — 真实场景端到端测试

> 核心原则：**用户输入 = 一大段自然语言，含多个意图、情绪、模糊表达、背景信息。AI 自行拆解→排序→执行→汇报。**

### 3.1 多意图拆解与排序

#### L3-01 查看 + 分析 + 修改 + 记录 (4意图混合)

**用户输入**:
> "我最近写的这个修仙故事，大纲和世界观都有了，也有几个角色，但总感觉设定上有些矛盾。你帮我从头到尾捋一遍——大纲、世界观、所有角色卡都看看。分析一下有没有设定冲突的地方，比如修炼体系前后不一、角色的能力超出体系限制、或者时间线对不上。发现问题后直接在对应文件里修改。然后把发现的所有问题和修改列成一个清单笔记。"

**隐含任务** (AI需自主发现):
1. list_directory 了解项目全貌
2. read_file 大纲 plot.md
3. read_file 世界观 worldbuilding.md
4. list_directory + read_file 所有角色卡
5. 分析设定一致性 (文本回复)
6. edit_file 修复发现的问题
7. write_note 问题清单笔记

**验证**: [ ] 遍历了所有设定相关文件 [ ] 分析有具体指出矛盾点 [ ] 修改了至少1处 [ ] 创建了笔记

#### L3-02 创作 + 灵感 + 模板 (多类型任务混合)

**用户输入**:
> "该写第2章了。大纲里第2章是剑魂觉醒的剧情——叶尘第一次感受到剑魂的力量，但不小心失控差点伤了林雨晴，然后陈远山出现帮他稳定剑意。写的时候注意几个点：第一，叶尘的内心挣扎要写出来，他既兴奋又害怕；第二，林雨晴的反应要细腻——她表面冷但内心的担忧要通过细节暗示；第三，陈远山的出场要有分量，他毕竟是剑皇。另外这段写完之后，帮我分析一下这一章的写作风格——我特别喜欢那种'外冷内热'的克制写法——建个风格模板以后复用。对了，写之前我有个灵感要记：'剑魂其实是上古剑神的执念，不是力量'，存到笔记。然后剑魂失控的那个场景要存为场景模板，叫'力量失控·初次觉醒'。"

**隐含任务**:
1. read_file 大纲 (确认第2章规划)
2. read_file 角色卡 (叶尘/林雨晴/陈远山)
3. read_file 第1章摘要 (剧情衔接)
4. read_file 第1章正文 (参考文风)
5. write_note "剑魂是执念不是力量" (灵感笔记)
6. create_file 第2章正文 (包含上述三个要求)
7. create_style_template (分析第2章风格)
8. create_scene_template (剑魂失控场景)

**验证**: [ ] 8个任务全部完成 [ ] 章节包含3个用户要求 [ ] 风格模板创建 [ ] 场景模板创建 [ ] 各任务按依赖排序(读→写→分析→模板)

#### L3-03 诊断 + 决策 + 分批执行

**用户输入**:
> "我不知道该不该继续往下写。已经写了两章了，但读者反馈说节奏太快——上一章还在青云宗，下一章就跳到天剑域了。你能不能帮我看看问题出在哪？把所有相关文件都读一下，给我一个诚实的评价。如果问题确实严重，帮我列一个修改方案。如果只是小问题，直接改就行。"

**隐含任务**:
1. read_file 所有章节+细纲+大纲
2. 分析节奏问题
3. **决策分支**: 严重→列方案(不直接改) / 小问题→直接改
4. 根据决策执行

**验证**: [ ] 分析了节奏问题 [ ] 有明确的决策(严重vs小问题) [ ] 决策后有对应行动 [ ] 没有盲目修改

#### L3-04 批量创建 + 格式一致性

**用户输入**:
> "我需要加一批配角进来，都是青云宗的：一个大师兄叫楚天阔，剑师境，性格正直但有点迂腐，是叶尘的早期竞争者最后成为朋友；一个药堂师姐叫沈青黛，精通炼丹术，性格温柔细心，后来喜欢上陈远山(这个伏笔要记笔记)；还有一个外门小师弟叫白小石，14岁，崇拜叶尘，是叶尘收的第一个跟班。都按标准格式创建角色卡。顺便在笔记里记一下这三个人的关系网——谁喜欢谁、谁和谁有矛盾、未来可能的剧情走向。"

**隐含任务**:
1. list_directory characters/ (了解命名)
2. read_file 已有角色参考格式
3. create_file 楚天阔.yaml
4. create_file 沈青黛.yaml
5. create_file 白小石.yaml
6. write_note 三人关系网+剧情走向

**验证**: [ ] 3个角色全部创建 [ ] 格式一致(参照已有) [ ] role枚举正确 [ ] 关系网笔记包含具体内容

#### L3-05 时序依赖——必须先读后写

**用户输入**:

**隐含任务** (强依赖):
1. read_file 第1章原文
2. edit_file 改写开头 (必须先做1)
3. read_file 第1章摘要 (必须先做2才能知道改了什么)
4. edit_file 修改摘要 (必须先做3)

#### L3-06 纠错——AI应该主动指出用户错误

**用户输入**:
> "我想把林雨晴的境界改成剑王境，她才19岁，这样比较厉害。还要给她加一个'能一剑斩断时空'的能力。"

**隐含任务**:
1. read_file 林雨晴角色卡
2. read_file 世界观 (检查修炼体系)

**验证**: [ ] AI指出了设定冲突 [ ] 给出了替代建议 [ ] 没有盲目执行 [ ] 确认后才修改

#### L3-07 情绪化输入——需要"翻译"成任务

**用户输入**:
